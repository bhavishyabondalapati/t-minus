# Decisions log

Each entry: what I decided, and why. Newest at the bottom.

1. **Node via conda.** A conda env named `t-minus` holds Node 22 (`conda activate t-minus`), so nothing is installed globally.
2. **ThreeUI source.** Used the free MIT "Community" npm package `@designcodeio/threeui` (repo MengTo/threeui, LICENSE = MIT). Pro/Beta source is not in that package, so every component imported is free. All seven requested components plus a Sign-up button exist in it. MIT only requires keeping the copyright notice, so the footer and README credit "ThreeUI by Meng To (MIT)". Catalog thumbnails/videos on threeui.com are NOT MIT, and I do not use them.
3. **ThreeUI components take no data props.** Landscape, Uplink, Gauges and Diagnostics render fixed content (iframes), the CRT and Arc are shader backdrops, and the dock has fixed labels. So real data (departures, countdown, on-time %) is drawn as accessible DOM text on top of them, and dock clicks are mapped to routes by event delegation. The visual layers are `aria-hidden`.
4. **"Get Started" button** is ThreeUI `LiquidMetalButton` (pill, `text` prop), which is free.
5. **One WebGL scene at a time** through a small scene manager (`src/lib/scene-manager.ts`). The active scene is mounted. Others show an SVG poster. Mobile, reduced motion and offscreen always get posters.
6. **argon2:** `@node-rs/argon2` (prebuilt binaries, works on Vercel without node-gyp).
7. **Rate limiting** is a Postgres fixed-window counter table. No Redis, so no extra paid service.
8. **Delay metric:** delay = actual arrival minus scheduled arrival. Actual arrival = first time the vehicle is seen STOPPED_AT the stop. If never seen, the last prediction before it vanished is used and flagged `source=last_prediction`.
9. **Landscape iframe.** ThreeUI's `LandscapeScene` wrapper hardcodes `sandbox="allow-scripts"` (opaque origin) and the scene stays blank in our app, though the same HTML renders fine with `allow-same-origin`. So `LandscapeLive` embeds the same ThreeUI `landscape.html` (copied from the package, served same-origin) with `allow-scripts allow-same-origin` and the wrapper's exact variant/time/weather query mapping. The copy has the scene's embedded music and sound clips removed (see `THIRD_PARTY_NOTICES.md`); the textures are kept.
10. **Scene slot = on screen.** A scene only competes for the one live WebGL slot while it is in the viewport. Priority: loader (100) > landscape (10) > arc (5) > CTA button (3) > board (2) > gauge/diagnostics (1). A per-panel "Live" switch pins a scene.
11. **Weather location** is fixed at downtown Boston (42.3601, -71.0589) rather than per stop. One forecast per 10 minutes is enough for a buffer.
12. **Direction** is inferred from stop order (destination after origin in route order = direction 0). On Red Line branches (Ashmont vs Braintree) that is approximate. Listed under known limits.
13. **Live URL.** `t-minus.vercel.app` already belongs to someone else's project, so the live alias is `https://t-minus-drab.vercel.app` (the one Vercel assigned to this project).
14. **Superseded by 18.** (Originally one database for everything.)
15. **E2E is local only.** CI runs lint, typecheck, unit tests and a build. The manual `e2e.yml` workflow was deleted (see 18) because it targeted deployed URLs.
16. **Git author** was rewritten to the GitHub noreply address before the first push so the public history does not expose a personal email.
17. **CSP** keeps `'unsafe-inline'` for scripts because Next.js emits inline bootstrap scripts and nonces would make every page dynamic. Everything else is locked to same-origin (plus Google Fonts for the ThreeUI loader).
18. **Dev and prod databases are separate, and E2E cannot touch production.** Production uses `DATABASE_URL` only when running on Vercel (`VERCEL` set) or when a script is explicitly run with `DB_TARGET=prod` (`npm run db:migrate:prod`, `db:seed:prod`). Everywhere else the code uses `DATABASE_URL_DEV` and throws if it is missing or points at the same host and database as production. Playwright refuses non-localhost base URLs and refuses to start if `VERCEL` or `DB_TARGET=prod` is set; its teardown deletes only `e2e-*@example.test` users. The `e2e.yml` workflow (which ran against a deployed URL) was removed.
19. **Demo account is read-only on the server (chosen over a nightly reset).** The demo account is shared and public, so a nightly reset would still let one visitor deface it for everyone until the reset. Creating or deleting commutes as the demo user returns 403 with `code: "demo_readonly"` and a plain message. The UI hides those controls and links to sign-up. Tested by unit tests (policy) and an E2E test (403 on POST and DELETE).
20. **Retention.** Raw `prediction_log` rows older than 14 days are rolled into `prediction_hourly` (per route, stop, direction and hour: count, delay count, delay sum, on-time count) and deleted, in one SQL statement so a row is never lost or counted twice. The cron endpoint runs it after reconciliation. Delay stats read raw rows plus hourly rows for the last 30 days. Hourly rows are kept 90 days. Rows are bucketed by actual arrival time.
21. **Fewer writes.** A prediction row is rewritten only when its predicted time moved by 30 s or more, and `last_seen_at` is no longer refreshed on every SSE tick. Before: about 6.5 updates per row. After: 0 updates for jitter under 30 s (measured: 200 unchanged ticks gave 0 writes versus 200 before).
22. **Diagnostics Panel contrast.** The ThreeUI Diagnostics shader renders as a near-flat tint, so the readable text panel (90% opaque) now fills the whole scene, which removed a stray lavender strip in light mode. Text contrast is AA or better in both themes (about 5.5:1 to 17:1).
23. **Retention roll-up is now tested against Postgres.** The roll-up SQL moved to `src/lib/server/rollup-sql.ts` (not server-only) so `tests/db/rollup.db.test.ts` runs the exact statement on the Neon dev branch inside `BEGIN ... ROLLBACK`, so it leaves no rows. It checks that only rows older than 14 days move, that buckets are per route, stop, direction and hour, that an existing bucket is added to rather than overwritten, that a second run moves nothing, and that real dev rows are untouched. It only runs with `npm run test:db` (`RUN_DB_TESTS=1`), never in CI, because CI has no database.
